## Verdict first

I cloned `indra2215/CIF` (single commit `5d78775`, 44 files, 10,755 lines) and ran it — not just read it: I installed `pymatgen/fastapi/uvicorn/mp-api`, booted the real FastAPI app with `TestClient`, executed the pipeline functions directly, and made live requests to COD and OQMD.

**The scaffold is correct; the product is not yet correct.** The architecture is coherent and matches its own design docs (doping-vs-undoped split, "never silently narrow polymorphs", stage separation). Nothing is corrupt — `python -m compileall` is clean, the CrystaLLM integration API is right, and COD's CSV columns are right. But there are **6 bugs that produce silently wrong or fabricated scientific output**, **1 missing dependency that stops the web app from starting**, **1 authentication hole**, and a set of validators that cannot fail.

## 3. Findings and minimal, non-breaking fixes

### P0 — blocking / wrong output

**F1. The web app answers its own questions, and that makes the "never silently pick" policy fail.**
`webapp.py:52-60` returns `options[0]` for every clarification. Follow the consequence chain: `classify.py:511` sets `is_doped = (answer == "Doped (substitutional)")`, and option 0 *is* that string → every non-stoichiometric formula is forced down the doping branch (verified: `Fe0.95O` → `is_doped=True`). In `matching.py:243-272`, when no candidate matches a user-requested space group, option 0 is a mismatched entry — so a request for `Pnma` silently returns the first wrong polymorph. The choices design in `matching.py`/`classify.py` is right; the caller defeats it.

### P1 — correctness / robustness

**F7. Free-text answers crash the pipeline.** `options.index(choice)` at `matching.py:272`, `matching.py:300`, `doping.py:142`, `generate.py:415` raises `ValueError` when the answer isn't an option — and the CLI *does* return free text (`user_interaction.py:29`). Add one helper and use it at the four sites:

```python
# user_interaction.py
def pick_option_index(choice: Optional[str], options: Optional[List[str]]) -> Optional[int]:
    """Index of `choice` in `options`, or None for free text / decline / timeout."""
    if not choice or not options:
        return None
    try:
        return options.index(choice)
    except ValueError:
        return None
```
Then at each site: `idx = pick_option_index(choice, options)` and use `idx` with an `is None` branch (for `matching.py`, `None` already means "surface all candidates"; for `doping.py`, keep the existing `candidates[0]` fallback; for `generate.py`, keep the lowest-energy candidate). Signature-compatible; new function only.

**F8. `co2` → `Co2`.** `_normalize_formula_input` (verified) silently reinterprets lowercase carbon dioxide as cobalt — a real chemistry change, and exactly the case `cif_pipeline_qa_brief.md` §1.2 asks you to decide. Mechanism (read from `classify.py:97-115, 139-161`): both readings score `+50` from `oxi_state_guesses`, and the stable sort keeps the first-built candidate `Co2`; I did not instrument the scorer, so treat the mechanism as inferred, the outcome as verified. Do **not** fix this with a score-margin rule — I verified `caco3 → CaCO3` works today and a margin rule would likely reject it (tie). The safe fix is a confirmation gate, not a silent rewrite: `/api/parse-formula` already returns `case_corrected`; make `/api/generate` refuse a repaired formula unless an explicit `confirmed_formula` is supplied, returning the candidate readings (`Co2` vs `CO2`).

**F9. Algebraic doping with parentheses isn't parsed, though the docstring says it is.** `_ALGEBRAIC_DOPING_RE` (`classify.py:43-46`) requires `La1-xSrx`; verified `_parse_algebraic_doping("La(1-x)Sr(x)MnO3 with x=0.25") → None` and `classify("La(1-x)SrxMnO3") → is_doped=False`. The module docstring (lines 288-297) and QA brief §2.2 both claim this works. Minimal, regression-free extension: add an alternative branch to the pattern (keeping groups 1/2 valid for the old form and reading `host_el = m.group(1) or m.group(3)`, `dopant_el = m.group(2) or m.group(4)`), and extend the tail-extraction regex at `classify.py:461` to accept `(x)`.

**F10. The repo's own co-doping benchmark silently runs as single-dopant.** `batch_processor.py:26` supplies `{"dopant": "Cr", "site": "Fe", "fraction": 0.025}`, but `classify.py:602` reads only `dopant_element`/`dopant_species` (while `site`/`fraction` *are* read at 603-604). Verified: that dict yields `co_dopants=[]`; the same dict with key `dopant_element` yields `[('Cr','Fe',0.025)]`. One-token fix — add `or item.get("dopant")` — plus replace the swallowing `except Exception: pass` (613-614) with a `log.warning`.

**F11. `P21/c` ≠ `P2_1/c`.** Verified: `_normalize_space_group('P21/c')` returns `'P21/c'` (all parse attempts fail) while `'P2_1/c'` returns pymatgen's odd symbol `'P12_1/c1'` — so a user asking for `P21/c` never matches a record stored as `P2_1/c`. Minimal fix: insert a spelling-repair attempt into the `attempts` list at `matching.py:75-82` (`P21/c → P2_1/c`, guarded so it can't double-underscore `P6_3/mmc`). **Why it's safe:** the public return contract is unchanged (`'Pnma'` stays `'Pnma'`, so `test_qa_status.py`'s expectations hold). **Unconfirmed:** I did not execute this patch; the durable fix is comparing by IT number, which would require updating your QA harness strings.

**F12. `MACE_DEVICE=cuda` never reaches MACE.** Grep-verified: `get_mace_device()` is used only by CrystaLLM (`generate.py:205`); `orchestrator.py:27` imports it and never calls it; `relax.py:76` and `relax.py:213` hardcode `device="cpu"`, and `generate.py:356` never passes a device. GPU users silently run on CPU. Fix: default `device=None` in `relax_with_mace`/`batch_relax` and resolve `get_mace_device()` inside (cache key at `relax.py:37` unchanged; only caller of `batch_relax` is `generate.py:356`).

**F13. Bond-length gate misses detached atoms.** `filter_rules.py:62-64` skips any site with no neighbour within 6 Å, so the "isolated/detached" branch is unreachable beyond 6 Å. Verified: `Na+Cl` 8.66 Å apart → `(True, [])`, as does a lone Na in a 10 Å box. Fix: record a violation instead of `continue` when `len(structure) > 1`. Touches `filter_candidates` only (line 173).

**F14. Authentication is decorative.** `webapp.py:520-533` returns success for any credentials (verified), and `hash(username)` is unstable across processes (verified), so no token can ever be validated. If the UI's login is meant to be real, use `hmac.compare_digest` against env-configured credentials plus an HMAC-signed token, and require it on `/api/generate`; gate with a `CIF_AUTH_ENABLED` flag so dev flows keep working. If it is cosmetic, delete it — a fake token is worse than none.
